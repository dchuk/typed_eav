A Value object reused for a later standalone save therefore inherits the stale bulk UUID forever.

Make the correlation genuinely ONE-SHOT PER SAVE, with cleanup that cannot be skipped:
  - the subscriber CONSUMES the id at its single read site - read into a local, then null the ivar, then build the row from the local - so a version row never sees a second use of the same stamp;
  - AND the ivar is cleared unconditionally at the end of the save lifecycle regardless of whether a version row was written. Consumption inside the subscriber alone is insufficient: when versioning is disabled, when the subscriber is skipped, or when no version row is written for any other reason, the stamp would still leak into the next save. Anchor the unconditional clear in `Value`'s own lifecycle, ordered AFTER the version row can be written - the existing `after_commit :_dispatch_value_change_*` chain (and the image dispatch declared after it) establishes the ordering convention to follow; declare the clear last so it runs last. Document the ordering dependency in a comment, because a future callback inserted after it would break the contract.

  - update the long explanatory comment at `value.rb:130-152` to document the consume-and-clear lifecycle and the three no-version-row cases.
