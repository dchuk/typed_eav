Domain constraints - `RangeBounded#validate_range`, `Optionable#validate_option_inclusion` / `validate_multi_option_inclusion`, `ValidatedString#validate_length` / `validate_pattern`, array size - are reachable only through `validate_typed_value(record, val)` and never run against a default. `apply_default` / `backfill_default!` then write that unvalidated default straight to the typed column.

Extend `validate_default_value` so that, when the cast SUCCEEDS and the casted value is non-nil, the default is also run through the field's own `validate_typed_value` and any resulting domain violation surfaces as an error on the field (on `:default_value`, matching the existing cast-invalid error's attribute and message style).

Implementation notes:
  - `validate_typed_value(record, val)` adds errors to the `record` it is handed via `record.errors.add(:value, ...)`. Route it through a throwaway error-collecting target (or an equivalent adapter) and translate any collected error into a `:default_value` error on the field - do NOT leak a `:value` error onto the Field, and do NOT mutate an unrelated record;
  - keep the existing early returns (`default_value_meta.blank?`, no `"v"` key, `raw.nil?`) and the existing cast-invalid error exactly as they are;
  - the check must work uniformly across field types, including Optionable types whose `allowed_option_values` are only populated after the field's options exist - a NEW (unsaved) Select field with no options yet must not be failed spuriously for having a default; skip domain validation when the type's domain is not yet determinable and document that carve-out in a comment;
  - do not change `apply_default` / `backfill_default!` - the fix is at Field validation time.
