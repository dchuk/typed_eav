`bench/` does not exist yet - create it. Four deliverables in one atomic commit:

(1) `bench/database_baseline.rb` - a read-only collector. Header comment must state: read-only; no DDL, no data mutation, no ANALYZE/VACUUM/stat reset; no dependency beyond the Rails/ActiveRecord/pg already shipped; and the determinism interpretation (sorted keys and stable structure, NOT byte-identical volatile numbers across DB states). Start with `# frozen_string_literal: true`.

Collect, per RESEARCH.md section F, against the five typed_eav tables (`typed_eav_sections`, `typed_eav_fields`, `typed_eav_options`, `typed_eav_values`, `typed_eav_value_versions`):
  - `pg_indexes.indexdef` - exact index definitions including WHERE / INCLUDE / opclass clauses.
  - `information_schema.columns` - name, data type, nullability, default per column.
  - `pg_constraint` - CHECK constraints (including `chk_te_fields_parent_scope_requires_scope` and `chk_te_sections_parent_scope_requires_scope`) and foreign-key definitions with their ON DELETE actions.
  - `pg_settings` - a curated planner-relevant subset only: `work_mem`, `shared_buffers`, `random_page_cost`, `effective_cache_size`, `default_statistics_target`, `max_connections`, `server_version` (`SELECT name, setting, unit FROM pg_settings WHERE name = ANY(...)`). Never `SET` or `ALTER SYSTEM`.
  - `pg_stat_user_tables` - `n_live_tup`, `n_dead_tup`, `seq_scan`, `idx_scan`, `last_vacuum`, `last_analyze`. Read whatever the DB currently reports; do NOT freshen them.
  - `pg_total_relation_size` / `pg_relation_size` / `pg_indexes_size` - bytes per table and per index.
  - Row counts via `SELECT COUNT(*)` per table.
  - `bytes_per_logical_value` = `pg_total_relation_size('typed_eav_values') / GREATEST(row_count, 1)`, emitted alongside an explicit companion field (e.g. `"row_count_zero": true`) plus a caveat string so a zero-row result is never mistaken for a measurement.

Split the JSON into two top-level sections: a stable `"schema"` section (columns, indexes, constraints) and a volatile `"runtime_snapshot"` section (row counts, table/index sizes, pg_stat rows, pg_settings, generated-at timestamp, server version). Sort every hash's keys before serialization; write pretty-printed JSON with a trailing newline. Include a top-level `"caveats"` array whose first entry states the empty-database limitation and that these numbers are non-decisional (Phase 2 requires a larger isolated volume/host for representative evidence).

Invocation: target the dummy app's test database, mirroring `spec/spec_helper.rb`'s bootstrap and the CI "Create database and run migrations" step. Document the exact command in the header comment and in the README; whichever form you pick (loading `spec/dummy/config/environment.rb` from inside the script vs `-r` on the command line), it must work verbatim as written with `RAILS_ENV=test`. Support writing to a path given as the first ARGV element, defaulting to `bench/results/phase-0-baseline.json`, and print the output path on success. Fail loudly with a clear message if the catalog reads error or the connection is unavailable - do not silently emit a partial document.
